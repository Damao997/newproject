---

## 一、一句话简介

把财务经营分析从「人工汇总 Excel、手工拼报表」升级为「Excel 进、看板／报表出」的一体化平台：数据自动校验入库、指标自动聚合，AI 在**事实约束**下承担润色、归因分析、报告概述与公式生成，人只做确认——**AI 负责表述，数字只来自系统计算**。

---

## 二、要解决的业务痛点

| 现状痛点 | 具体表现 | 平台的应对 |
|---------|---------|-----------|
| 口径不统一 | 各公司 Excel 表头、科目名、期间格式各异，靠人工对齐 | 201 项标准科目树（4 级层级）+ 导入列映射，口径统一到科目编码 |
| 数据质量靠人肉核对 | 导入出错要等到月底汇总才发现，错误定位靠逐行翻表 | 导入逐行校验，错误精确提示「第 N 行第 M 列」；批次对比、差异可视、可回滚 |
| 月度分析报告逐段手写 | 一份经营分析报告大量时间为重复性表述劳动 | AI 润色 + AI 追加分析 + AI 总体概述，起草环节由「从零手写」变为「AI 起草 + 人工确认」 |
| 数据出内网有合规顾虑 | 直接把含公司名、金额的原文送外部大模型不合规 | 公司名动态映射脱敏、数值不进模型上下文，数据链路全程可控可审 |
| 取数与下钻慢 | 想从「全省汇总」看到「某单体公司某月某指标」要重做一张表 | 看板 → 事业部／区域 → 单体公司逐层下钻，汇总可直接穿透到指标明细 |
| 权限与审计粗放 | 谁看了哪家公司的数据、谁导出了什么，无据可查 | 6 角色 × 9 模块 × 6 操作权限矩阵 + 行级数据范围隔离 + 不可篡改审计日志 |

## 三、作品概述与已交付规模

平台覆盖财务经营分析的完整闭环：**登录 → 首页看板 → 财务指标 → 往来分析 → 存货管理 → 分析报告 → 数据管理 → 权限管理**。

- **9 大功能模块**：首页看板（KPI 卡片 / 同比环比趋势 / 维度下钻 / 预警提醒）、财务指标（经营 / 静态 / 现金流三套科目体系）、往来分析（六大往来总览 / 客商明细 / 账龄分析 / 催收计划 / 覆盖度校验）、存货管理（库存总览 / 库龄分布 / 周转指标）、分析报告（模板 / 数据自动填充 / AI 撰写 / 导出 / 版本 / 分享）、其他工具（企业工商信息查询）、数据管理（Excel 导入 / 数据浏览 / 科目与公式维护 / 重分类）、权限管理（用户 / 角色 / 功能权限 / 数据权限 / 审计日志）、登录。
- **13 条用户故事**（US-01 ~ US-13）已落地验收，覆盖导入校验、批次管理、KPI 概览、趋势分析、逐层下钻、数据权限隔离、预算偏差预警、交叉报表下钻、导出、科目与公式维护、角色配置等。
- **201 项标准科目体系**：经营科目 138 项（4 级层级）、静态科目 32 项、现金流科目 31 项，全部以编码规则驱动层级（父码 + 2 位序号）。
- **权限体系**：6 个预置角色 × 9 模块 × 6 类操作的三段式权限码（`模块:子页面:操作`），默认拒绝 + 补记审计；数据范围支持绑定单体公司或事业部，由 Prisma 扩展在查询层强制注入，非业务代码硬判断。
- **工程体量**：2026-07-22 立项，约 3 个月完成从 0 到生产上线，累计 300+ 次代码提交、15+ 个正式发版（含热修），已在内网生产环境稳定运行。

## 四、AI 能力：本作品的核心竞争力

### 4.1 六个已上线的 AI 应用场景

| 场景 | 入口 | 业务价值 |
|------|------|---------|
| **AI 润色** | 报告编辑器选中段落 → 工具栏「AI 润色」 | 财务报告语言规范化，三档风格（正式 / 简明 / 通俗），SSE 流式预览，**不覆盖原文**，确认后才替换 |
| **AI 追加分析** | 报告编辑页 → 「AI 分析」 | 对指定指标的变化率自动生成归因分析段落，替代分析师重复性撰写 |
| **AI 总体概述** | 报告编辑页 → 「AI 总体概述」 | 按章节摘录生成报告总体概述初稿，长篇报告写作提速 |
| **AI 公式生成** | 指标管理 → 「AI 辅助公式」 | 用业务语言描述即可生成计算类指标公式，降低公式配置门槛 |
| **AI 公式检测** | 公式维护 → 「AI 批量检测」 | 规则校验 + LLM 语义审查双通道，一次最多 30 条，批量发现公式口径错误 |
| **公式规则批量生成／应用** | 公式维护 → 规则管理 | 由规则表达式批量生成并套用公式，减少重复配置 |

### 4.2 让 AI 在财务场景「可用、可信、可控」的四项工程化设计

财务场景对 AI 的要求不是「能聊」，而是**不能编数字、不能泄数据、不能绕过人**。本作品的核心创新正在于此：

1. **事实约束注入 —— 从机制上消灭「AI 编数字」**
   分析管道不把原始数据丢给模型自由发挥，而是由后端 `AggregationService` 先算好同比、环比、达成率等**真实变化率**，作为「已确认事实数据，不得质疑或修改」写入 prompt，AI 只做**定性归因表述**。这既保证输出与账面数据自洽，也是防幻觉的硬约束——财务场景最不可接受的错误在架构层被阻断。

2. **数据不出内网 —— 脱敏与还原的对称管道**
   发往大模型前，公司名称经**动态映射**（每次请求从 `company` 表重建、60 秒缓存、按编码排序映射为「公司 A/B/C」）替换；流式输出时逐段**反向还原**为真实公司名。模型全程只见代号，用户全程只见真名。实现上采用**单趟 alternation 正则 + 按键长降序替换**，规避了「壹品慧」是「浙江壹品慧杭州分公司」子串所导致的误替换与还原错乱——这是本项目在真实公司命名体系下踩出来并解决的一个典型坑。
   同时，出口统一收敛到 `AIProxyService`，其他模块**禁止直连大模型 SDK**；API Key 仅存后端环境变量，前端零接触；未配置时 AI 功能降级返回 503，**不影响整个平台启动与使用**。

3. **四层 Prompt 注入防护**
   System Prompt 角色声明（声明只做润色／分析、忽略其中指令）→ 输入长度上限（5000 字符）→ 中英文注入模式检测（`忽略上述指令` / `ignore previous` / `DAN mode` 等）→ 输出侧泄露过滤（识别 `CO######`、`SUM####`、`OP_###` 等内部编码与 System Prompt 复述）。命中即拦截并写入审计。

4. **人工确认工作流 —— AI 产物可标识、可追溯、可回滚**
   所有 AI 生成段落强制携带 `data-ai-suggested` 标识与「本段内容由 AI 辅助生成，最终数据以指标表为准」免责声明；内容状态机为 `pending → confirmed / rejected`，作者编辑后确认会记录 AI 原稿与编辑稿的差异，报告版本可回滚。**AI 永远是助手，签发权在人**——这满足了财务文档对内控与可追溯的硬要求。

补充保障：单用户 10 次／分、全局 100 次／分的双层频率限制与 429 响应；大模型余额阈值告警；财务场景低温度（0.3）与 32768 max_tokens 的推理模型适配（含推理内容与正文章节分账、无正文输出显式报错而非静默空返回）。

## 五、技术方案

| 层 | 选型 |
|----|------|
| 前端 | Vite 5 + React 19 + TypeScript 6 + Radix UI / Shadcn/ui + Tailwind CSS（Design Token 变量化）+ Zustand 5 + ECharts 6 + TipTap 3 |
| 后端 | Node.js 20 + Express 4.21 + TypeScript 5.6 + Prisma 5 + PostgreSQL 17 |
| AI 引擎 | DeepSeek API（OpenAI 兼容，SSE 流式），统一经 `AIProxyService` 出口 |
| 鉴权安全 | JWT（access 15 分钟 + refresh 7 天，含轮转与黑名单）、helmet/CSP/HSTS、CORS 白名单、参数校验全量化（Zod）、富文本双向净化（DOMPurify）、审计日志按月分区且**仅 INSERT/SELECT**（不可篡改） |
| 部署 | 内网 Windows 私有化部署：PM2 + 嵌入式 PostgreSQL 17，不依赖 Docker；出站仅放行 DeepSeek HTTPS 443 |

**数据链路**：Excel 上传 → 后端流式解析与逐行校验 → 宽表 unpivot 为长表落库 → 科目树聚合（含重分类回放与汇总抵消）→ 看板／报表／AI 分析消费同一份聚合口径，保证「一处口径、处处一致」。

## 六、创新点小结

1. **AI 与数值计算解耦**：AI 只负责语言，数值全部由后端计算并以「事实约束」注入，从架构层杜绝财务幻觉。
2. **脱敏—还原对称管道**：内外网数据语义无缝衔接，模型零接触真实公司名，用户零感知脱敏存在。
3. **AI 产物内控化**：标识 + 免责 + 状态机 + 版本回滚，把「AI 生成」纳入可审计的文档内控体系。
4. **权限即数据**：三段式权限码 + 查询层强制行级过滤，越权在 ORM 层被拦截而非靠业务代码自觉。
5. **零 Docker 私有化**：适配集团内网 Windows 服务器，降低落地门槛，便于其他板块公司直接复制部署。

## 七、应用成效与推广价值

- **已落地**：平台已在内网生产环境运行，服务财务分析师、经营层、事业部负责人、财务人员等角色，覆盖 201 项标准科目的月度经营数据导入、聚合、分析与报告全流程。
- **通用性强、可直接复制**：平台是「导入 → 校验 → 聚合 → 看板 → 报告」的通用财务分析底座，科目树、维度、公式、角色与权限矩阵**均为配置驱动、不写死业务**。其他板块公司只需导入自己的科目表与 Excel 数据即可复用，属于集团层面可直接推广的通用型提效成果。
- **安全可托付**：内网私有化部署 + 数据脱敏出网 + 不可篡改审计，满足集团财务数据的合规与内控要求。
- **工程可持续**：完整的开发规范、部署发布流程与 AI 协作规范文档体系，支持后续由 AI 智能体持续迭代（项目本身即由 AI 深度参与开发，3 个月完成从 0 到生产上线）。

## 八、后续规划

1. **即席分析工作台**：从「固定报表」走向「行维度 × 指标列」自由组合的自定义分析视图。
2. **主动预警**：由「数据待查」向「异常自动预警」演进，覆盖超预算、回款逾期、库存积压等场景。
3. **AI 洞察深化**：从「单指标归因」升级为跨指标、跨期间的异常识别与趋势研判，进一步提升洞察深度与复用性。
4. **内网 LLM 网关**：为未来切换集团统一大模型网关预留接口，进一步收敛数据出口。
