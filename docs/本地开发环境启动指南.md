# 本地开发环境启动指南

> **适用项目**：浙江壹品慧财年经营数据分析平台（`yipinhui_finance_analytics`）
> **更新日期**：2026-07-30
> **适用系统**：Windows / macOS / Linux

---

## 一、环境要求

| 依赖 | 最低版本 | 说明 |
|------|----------|------|
| Node.js | ≥ 18 | 推荐 20 LTS；多个依赖要求 `node >= 18` |
| npm | ≥ 9 | 随 Node.js 附带 |
| Git | ≥ 2.30 | 版本管理 + Husky hooks |

> **无需安装 PostgreSQL**：项目使用 `embedded-postgres` 在用户态运行数据库，无需管理员权限、无需 Docker。

---

```
pj3/

│   ├── prisma/      # schema + migrations + seed
```

## 三、启动前准备

### 3.1 克隆仓库

```bash
git clone <仓库地址> pj3
cd pj3
```

### 3.2 安装依赖

项目有三个 `package.json`，需分别安装：

```bash
# 根目录（husky + lint-staged）
npm install

# 后端
cd server
npm install

# 前端
cd ../web
npm install
```

### 3.3 配置环境变量

进入 `server/` 目录，复制示例文件并修改：

```bash
cd server
cp .env.example .env
```

编辑 `.env`，**以下为必填项**：

| 变量 | 必填 | 说明 | 示例值 |
|------|:----:|------|--------|
| `DATABASE_URL` | ✅ | PostgreSQL 连接串 | `postgresql://postgres:postgres@localhost:5432/yipinhui_finance?schema=public` |
| `JWT_SECRET` | ✅ | Access Token 签名密钥（≥32 字符） | 随机生成 |
| `JWT_REFRESH_SECRET` | ✅ | Refresh Token 签名密钥（≥32 字符） | 随机生成 |

> ⚠️ **安全红线**：`JWT_SECRET` / `JWT_REFRESH_SECRET` 缺失或长度不足 32 位时，后端**拒绝启动**。

**生成安全密钥**：

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

**完整 `.env` 模板**（可直接用于本地开发）：

```ini
# ===== 数据库 =====
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/yipinhui_finance?schema=public"

# ===== JWT =====
JWT_SECRET="<生成的随机密钥1>"
JWT_REFRESH_SECRET="<生成的随机密钥2>"
ACCESS_TOKEN_TTL="15m"
REFRESH_TOKEN_TTL="7d"

# ===== 服务 =====
PORT="3001"
NODE_ENV="development"

# ===== CORS =====
FRONTEND_ORIGIN="http://localhost:5173"

# ===== 密码哈希 =====
BCRYPT_COST="12"

# ===== 日志 =====
LOG_LEVEL="DEBUG"

# ===== 财年 =====
FISCAL_START_MONTH=4

# ===== 种子演示口令 =====
SEED_DEFAULT_PASSWORD="Yipinhui@2026"

# ===== AI（DeepSeek，可选）=====
DEEPSEEK_API_KEY=""
DEEPSEEK_API_BASE="https://api.deepseek.com/v1"
DEEPSEEK_MODEL="deepseek-v4-flash"
```

> 💡 AI 功能为可选项：未配置 `DEEPSEEK_API_KEY` 时 AI 相关接口返回 503，但不影响应用正常启动和其他功能。

## 四、启动步骤（按顺序执行）

项目需要 **3 个终端窗口**，按以下顺序启动：

### 步骤 1：启动数据库（终端 1）

```bash
cd server
npm run db:local
```

**说明**：
- 使用 `embedded-postgres` 在用户态启动真实 PostgreSQL 17
- 数据持久化于 `server/.pgdata/`（已 gitignore）
- 首次运行会自动下载 PostgreSQL 二进制文件并初始化数据目录
- 监听端口：**5432**
- 该命令为**阻塞进程**，保持运行不要关闭
- 看到 `[db] 就绪。保持运行中，按 Ctrl+C 停止。` 表示数据库已就绪

**连接信息**：

| 参数 | 值 |
|------|-----|
| Host | localhost |
| Port | 5432 |
| User | postgres |
| Password | postgres |
| Database | yipinhui_finance |

### 步骤 2：初始化数据库 + 启动后端（终端 2）

**首次启动**需执行数据库初始化（仅需一次）：

```bash
cd server

# 生成 Prisma Client（类型安全的数据库访问层）
npm run prisma:generate

# 执行数据库迁移（创建表结构）
npm run prisma:migrate

# 导入种子数据（角色、权限、公司、演示用户）
npm run prisma:seed
```

> 💡 也可使用一键命令完成上述三步（注意：`setup` 会同时启动 db:local，如已在终端 1 运行则分开执行）：
> ```bash
> npm run setup
> ```

**启动后端开发服务器**：

```bash
npm run dev
```

**说明**：
- 使用 `tsx watch` 实现热重载（文件修改后自动重启）
- 监听端口：**3001**
- 访问地址：`http://localhost:3001`
- API 前缀：`/api/v1`
- 看到 `后端服务已启动：http://localhost:3001（env=development）` 表示启动成功

### 步骤 3：启动前端（终端 3）

```bash
cd web
npm run dev
```

**说明**：
- 使用 Vite 开发服务器，支持 HMR 热更新
- 监听端口：**5173**
- 访问地址：`http://localhost:5173`
- 已配置代理：`/api/v1` 请求自动转发到后端 `http://localhost:3001`
- 开启 `host: true`，局域网设备可经 `http://<本机IP>:5173` 访问

## 八、常见启动问题排查

### 8.1 数据库启动失败

**症状**：`npm run db:local` 报错退出

| 可能原因 | 解决方法 |
|----------|----------|
| 端口 5432 被占用 | 检查是否有其他 PostgreSQL 实例运行：`netstat -ano \| findstr 5432`，关闭冲突进程 |
| 首次下载二进制超时 | 检查网络/代理设置，重新执行 `npm run db:local` |
| `.pgdata` 目录损坏 | 删除 `server/.pgdata/` 目录后重新初始化（数据会丢失） |
| `.node` 原生绑定缺失 | 执行 `npm install` 重新安装依赖 |

### 8.2 后端启动失败

**症状**：`npm run dev` 报错

| 错误信息 | 原因 | 解决方法 |
|----------|------|----------|
| `环境变量 DATABASE_URL 未配置，服务拒绝启动` | `.env` 文件缺失或变量未填 | 确认 `server/.env` 存在且 `DATABASE_URL` 已配置 |
| `环境变量 JWT_SECRET 长度不足（至少 32 位）` | 密钥过短 | 重新生成 ≥32 字符的随机密钥 |
| `环境变量 JWT_SECRET 未配置` | 缺少 JWT 密钥 | 在 `.env` 中配置 `JWT_SECRET` 和 `JWT_REFRESH_SECRET` |
| `环境变量 BCRYPT_COST 非法` | cost 值 < 12 | 设置 `BCRYPT_COST="12"` 或更高 |
| `ECONNREFUSED` 连接数据库失败 | 数据库未启动 | 确认终端 1 的 `npm run db:local` 正在运行 |
| `Can't reach database server` | Prisma 无法连接 | 检查 `DATABASE_URL` 中的端口/用户名/密码是否正确 |

### 8.3 Prisma 迁移失败

**症状**：`npm run prisma:migrate` 报错

| 可能原因 | 解决方法 |
|----------|----------|
| 数据库未启动 | 先启动 `npm run db:local` |
| 迁移冲突（开发环境） | 删除 `server/.pgdata/` + 重新 `npm run db:local` + `npm run prisma:migrate` |
| Prisma Client 未生成 | 先执行 `npm run prisma:generate` |

### 8.4 前端启动失败

**症状**：`npm run dev` 报错

| 可能原因 | 解决方法 |
|----------|----------|
| 端口 5173 被占用 | Vite 会自动尝试 5174；或手动关闭占用进程 |
| 依赖安装不完整 | 删除 `node_modules` + `package-lock.json` 后重新 `npm install` |
| Node.js 版本过低 | 升级到 Node.js ≥ 18（推荐 20 LTS） |

### 8.5 API 请求 404 / CORS 错误

| 可能原因 | 解决方法 |
|----------|----------|
| 后端未启动 | 确认 `http://localhost:3001` 可访问 |
| 代理未生效 | 确认前端通过 `http://localhost:5173` 访问（而非直接访问 3001） |
| CORS 配置不匹配 | 检查 `.env` 中 `FRONTEND_ORIGIN` 是否包含当前前端地址 |

### 8.6 AI 功能不可用

**症状**：AI 相关接口返回 503

| 可能原因 | 解决方法 |
|----------|----------|
| 未配置 API Key | 在 `.env` 中设置 `DEEPSEEK_API_KEY` |
| 模型名错误 | 必须为 `deepseek-v4-flash` 或 `deepseek-v4-pro`（旧版名称已废弃） |
| 网络不通 | 确认能访问 `https://api.deepseek.com`（需防火墙放行 443 出站） |

### 预提交质量门

项目配置了 Husky + lint-staged，`git commit` 前会自动执行 lint 检查。确保代码符合规范后再提交。

```bash
cd server
npm run prisma:studio
```

打开 `http://localhost:5555` 即可浏览/编辑数据库表数据。

### 重置数据库（开发环境）

如需完全重置数据库：

```bash
# 停止 db:local（Ctrl+C）
# 删除数据目录
rm -rf server/.pgdata    # Windows: rmdir /s /q server\.pgdata

# 重新启动并初始化
npm run db:local         # 终端 1
npm run prisma:generate  # 终端 2
npm run prisma:migrate
npm run prisma:seed
```
