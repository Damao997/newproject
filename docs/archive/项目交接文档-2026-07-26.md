## 一、项目概况

### 1.1 产品定位

"Excel 进、看板/报表出"的内部管理口径财务数据平台。单主体、人民币、简体中文，内网私有化 Docker 部署。

### 1.2 技术栈

| 层 | 选型 |
|----|------|
| 前端 | Vite 5 + React 18 + TypeScript + Radix UI + Shadcn/ui + Tailwind CSS 3 + ECharts + Ant Design 5（仅 ProTable） |
| 后端 | Node.js + Express 4.21 + TypeScript + Prisma 5.22 + PostgreSQL 15 |
| AI | DeepSeek API（SSE 流式，模型 `deepseek-v4-flash`） |
| 测试 | Vitest + @testing-library/react + supertest |
| 本地数据库 | embedded-postgres（用户态运行，数据持久化于 `server/.pgdata`） |

### 3.2 关键表结构说明

## 四、系统架构与中间件

### 4.1 中间件执行链（app.ts 装配顺序）

```
请求 → traceId → helmet → cors → express.json(1mb) → generalRateLimiter(/api/v1) → 路由 → 404 → errorHandler
```

路由内部再叠加：`authenticate → requirePermission → scope → softDelete → audit`

### 4.2 中间件清单（15 个文件）

| 中间件 | 文件 | 职责 |
|--------|------|------|
| trace-id | `trace-id.ts` | 链路追踪 ID（X-Trace-Id） |
| helmet | `helmet.ts` | HTTP 安全头（CSP/HSTS/X-Frame-Options） |
| cors | `cors.ts` | 跨域（仅允许 FRONTEND_ORIGIN） |
| rate-limit | `rate-limit.ts` | 通用限流（100次/分钟） |
| ai-rate-limit | `ai-rate-limit.ts` | AI 接口专用限流 |
| auth | `auth.ts` | JWT 验证（access token + refresh 黑名单） |
| permission | `permission.ts` | 三段式权限校验（默认拒绝） |
| scope | `scope.ts` | 数据范围注入（Prisma $extends） |
| soft-delete | `soft-delete.ts` | 软删除过滤（status='active'） |
| audit | `audit.ts` | 审计记录（异步写入，不阻塞响应） |
| error-handler | `error-handler.ts` | 全局错误处理 + 404 |

### 4.3 数据权限（scope.ts）核心逻辑

三级优先级：
1. `user.company_code` 非空 → 精确绑定单体公司
2. `user.org_scope_bu` 非空 → 通过 company.businessUnit 映射为多公司
3. `role.scope_value='*'` → 全量访问
4. 兜底 → `{ type: 'none' }`（空结果，默认拒绝）

受 scope 过滤的模型：FactOperating、FactStatic、FactBudget、TransactionDetail、AgingRecord、CollectionPlan、InventoryRecord、Counterparty

## 八、权限安全相关

### 8.1 认证体系

- JWT 双 Token：access（15min）+ refresh（7day）
- Refresh Token 轮转：刷新后旧 token 失效
- Token 黑名单：PostgreSQL `token_blacklist` 表持久化
- 登出：将 refresh token jti 写入黑名单

### 8.2 权限模型

- **5 个预置角色**：admin / finance_manager / department_manager / viewer / finance_analyst_it
- **三段式 resource 编码**：`模块:子页面:操作`（如 `data:import:upload`）
- **action 枚举**：view / create / update / delete / export / import
- **默认拒绝**：未声明权限的路由返回 403
- **禁止硬编码 admin 判断**：统一通过 `scope_value='*'` 判定全量

### 8.3 数据权限（scope）

- Prisma `$extends` 自动拦截读操作
- 三级优先级：company_code 精确绑定 > org_scope_bu 事业部映射 > scope_value='*' 全量
- 兜底：无范围返回空结果（防越权）

### 8.4 安全措施清单

| 措施 | 实现位置 |
|------|----------|
| HTTP 安全头 | `middleware/helmet.ts` |
| CORS 白名单 | `middleware/cors.ts` |
| 通用限流 | `middleware/rate-limit.ts`（100次/分） |
| AI 专用限流 | `middleware/ai-rate-limit.ts` |
| 软删除过滤 | `middleware/soft-delete.ts` |
| 审计日志 | `middleware/audit.ts`（异步，不阻塞） |
| Prompt 注入防护 | `lib/prompt-guard.ts`（四层） |
| 数据脱敏 | `lib/desensitize.ts`（公司名→代号） |
| 富文本净化 | `lib/sanitize.ts`（sanitize-html） |
| 文件上传安全 | multer fileFilter + MIME magic number |
| 密码哈希 | bcryptjs（cost ≥ 12） |
| JWT 安全红线 | 密钥缺失/过短拒绝启动 |

## 九、AI 模块（DeepSeek 集成）

### 9.1 架构

```
前端 → /api/v1/ai/* → ai-rate-limit → authenticate → requirePermission
  → AIProxyService（唯一 LLM 出口）
    → prompt-guard（输入防护）
    → desensitize（脱敏）
    → deepseek.ts（chatComplete / chatStream）
    → filterOutput（输出过滤）
    → restoreCompanyMap（还原）
```

### 9.2 已实现的 AI 功能

| 功能 | 端点 | 模式 | 说明 |
|------|------|------|------|
| AI 润色 | POST `/ai/polish` | SSE 流式 | 三种风格（formal/concise/plain），公司名脱敏→还原 |
| AI 追加分析 | POST `/ai/analyze` | SSE 流式 | 基于真实同比/达成率事实约束生成分析初稿 |
| AI 公式生成 | POST `/ai/formula` | 同步 | 自然语言→四则运算公式，仅传科目结构不传数值 |
| AI 公式检测 | POST `/ai/formula/check` | 同步 | 批量审查（≤30条），规则校验 + LLM 语义审查 |
| 公式规则 CRUD | GET/POST/PUT/DELETE `/ai/formula-rules` | 同步 | 规则管理 + 批量生成/应用 |
| 批量预览 | POST `/ai/formula/batch-preview` | 同步 | 按规则批量生成公式（不落库） |
| 批量应用 | POST `/ai/formula/batch-apply` | 同步 | 批量写入公式到 metric 表 |

### 9.3 双管道脱敏策略

**Polish 管道（润色）**：
- 输入防护（四层 Prompt 注入检测）→ 公司名扫描→动态脱敏（公司名→代号）→ DeepSeek SSE → 输出过滤 → 反向还原（代号→真实公司名）

**Analyze 管道（追加分析）**：
- 百分比/变化率不脱敏 → 公司名→别名 → 不发绝对金额 → 事实约束注入 → DeepSeek SSE → 输出过滤 → 还原公司名

**Formula 管道（公式生成/检测）**：
- 仅传科目结构（编码+名称+层级），不传任何数值、不涉及公司隐私，跳过脱敏

### 9.4 DeepSeek 配置

- 唯一出口：`server/src/lib/deepseek.ts`（chatComplete / chatStream）
- 模型：`deepseek-v4-flash`（默认）/ `deepseek-v4-pro`
- 旧版模型名（deepseek-chat/flash）已不被接受，会返回 400
- 未配置 `DEEPSEEK_API_KEY` 时 AI 功能不可用（抛 503），但应用仍可正常启动

- `ai-generate-error.png` 截图表明 AI 功能曾出错（仍在联调排错阶段）
- 内网部署需防火墙放行 `https://api.deepseek.com`
