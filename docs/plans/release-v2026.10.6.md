## 发布门禁与进程隔离

功能分支先经 PR/CI 合入 develop，develop 再经 PR/CI 合入 main；正式注释 tag 指向最终 main 合并提交，不直推 main。提交前完整 npm run verify 在已备份独立测试库执行；完整报表 10 项逐单元格契约、96 组四主题/三尺寸工作台、既有八项全站浏览器回归、16 组真实数据只读验收及最终手机补测通过。详细结果见 frontend-redesign-verification.md 第十二节。

发布前发现旧部署等待逻辑按目录 basename 匹配，会将 D:/ZJYPHFA-dev 与同名开发工作树错误视为生产进程。本次修正为规范化完整生产路径及目录分隔符，只等待本生产目录的 PG、后端与构建进程。check-deploy-process-scope.ps1 执行真实等待函数及进程/等待替身，验证开发与测试进程不阻塞、生产未退出仍拒绝、生产退出后继续。

旧生产 tag 的部署脚本含该缺陷。首次引导使用经正式 tag 源码一致性核对的本版本 server/scripts/deploy-zjyph.ps1，显式 ProdDir=D:/ZJYPHFA，在生产目录运行；仍是唯一部署脚本，仍完整执行 tag/main 校验、强制备份、分阶段构建、迁移、切换及冒烟。没有手工覆盖 dist，也不停止开发库以绕过等待。
