# 移动端表格卡式化评估

> 状态：评估完成，暂不实施（记录在案，避免范围蔓延）
> 日期：2026-08-26
> 范围：Phase 4 方向 5（导出体验统一 + 移动端表格卡式化评估）Step 3

## 1. 现状能力盘点

### 1.1 DataTable 通用组件（web/src/components/data-table/data-table.tsx）

| 能力 | 现状 | 移动端表现 |
|------|------|-----------|
| <640px 横向滚动 | 无 maxHeight 时外层 `overflow-x-auto`；有 maxHeight 时 `overflow-auto`（横+纵双滚动） | 表格保持完整列宽，窄容器下走横向滚动；`whitespace-nowrap` 杜绝单元格压缩换行 |
| density 三档 | `default`（表头 h-11 / 单元格 p-4）、`dense`（h-8 / px-4 py-1.5）、`compact`（h-8 / px-3 py-2）；兼容旧 `dense` 布尔 | 紧凑档在移动端可减少行高，但列数多时仍靠横向滚动 |
| 冻结列 | 列级 `sticky` prop（`'left'`/`'right'`/`true`），sticky left-0/right-0 + z 层级 + `TABLE_STICKY_CELL_BASE` 阴影分隔；与 sticky 表头交叠处 z-30 | 支持横向滚动时关键列/操作列固定，但**当前各页面列定义基本未启用**（users/browse/formula 等均未传 `sticky`） |
| maxHeight | 限高模式：`flex-1 min-h-0` 参与 flex 链撑满，内部垂直滚动 + 表头 sticky | 视口撑满页面（账龄/指标/浏览页）表格高度由 `calc(100dvh - stickyTop - 24px)` 驱动，移动端高度充足 |

### 1.2 页面表格移动端实际表现（抽查 3 处）

#### 账龄明细（transactions/aging.tsx）

- 实现：自建 `<table>`（非 DataTable），`minWidth: 1240` + `overflow-auto` + sticky 表头 + 底部合计行。
- 列构成：约 13 列（公司/往来类型/往来对象/科目/期初/期末/1-30/31-60/61-90/91-180/181-365/365+ 等），小计/合计行聚合。
- 移动端表现：**纯横向滚动 1240px 宽表**；表头 sticky 保证滚动时列名可见；无冻结列（首列公司不可固定）。
- 行内无操作按钮（分析/导出在页头与筛选卡），无触控目标问题；汇总/统计属性强（小计/合计矩阵），卡式化会破坏行内聚合的对照结构。

#### 存货明细（inventory/detail-table.tsx）

- 实现：自建 `<table>`，`min-w-[880px]` + `max-h-[520px] overflow-auto`（横+纵双滚动）。
- 冻结列：选择列 sticky left-0（w-9）+ 公司/品类列 sticky left-9（`max-w-[180px] truncate`）；表头 sticky top-0；合计行 sticky bottom-0。
- 行内操作：**「分析」按钮位于表格最右侧且不冻结**（detailDim=company/detail 模式），移动端需横向滚动到最右才能触达；按钮 `h-7`（28px）低于 40px 触控目标。
- 移动端表现：左侧 2 列（选择框+主体名）固定 + 880px 横向滚动，**关键标识列已固定、操作列未固定**。

#### 指标树（components/subject-tree/metric-tree.tsx）

- 实现：自建树表，科目列 sticky left-0 `min-w-[160px]` + 右侧阴影分隔；`overflow-x-auto + overflow-y-auto` 双滚动容器 + `minWidth` 兜底。
- 移动端表现：科目列固定（层级缩进 + 展开/折叠箭头不被横向滚动截断），数值列横向滚动；表头双行 sticky。
- 层级语义（缩进 + 展开/折叠）强依赖表格行结构，卡式化会破坏科目树的层级感知。

## 2. 卡式化适用性分析

| 表格类型 | 代表页面 | 列数 | 卡式化适用性 | 理由 |
|----------|---------|------|-------------|------|
| 明细型 | 存货明细（detail 视图） | 7-8 | **值得** | 行内字段为独立事实（公司/品类/五列金额），卡式化为"一行一卡"后移动端可读性显著提升 |
| 明细型 | 账龄明细 | 13+ | **部分值得**（成本高） | 小计/合计行 + 分段矩阵的聚合对照语义强，卡式化需重排聚合行；字段 13 个卡片高度过大 |
| 层级型 | 指标树/科目树 | 6-8 | **不适合** | 缩进 + 展开/折叠 + 层级底色是核心语义，卡式化破坏层级感知；现状"科目列固定+数值横滚"已可用 |
| 汇总/统计型 | 数据预览交叉表、用户/角色/审计/公式维护等 DataTable 页面 | 5-10 | **不必要** | 列数少、行内无密集操作，横向滚动可接受；卡式化反而丢失表格的横向对照能力 |

**结论**：全站仅「存货明细」一类值得卡式化，覆盖面窄；且其当前已具备"关键列固定 + 合计行吸底"的可用基线，卡式化增量收益有限。

## 3. 建议（Phase 5 前不做全站卡式化）

优先实施三项低成本改进（均为局部改动，不涉及新组件体系）：

1. **关键操作列固定**：存货明细的「分析」操作列加 `sticky right-0`（自建表手动加 sticky + 背景色/z 层级；DataTable 页面直接传 `sticky="right"`），避免移动端滚到最右才能触达操作。
2. **触控目标 ≥40px**：存货明细「分析」按钮 `h-7 px-2 text-xs` → 最小 `h-10`（或提升为 `size="sm"` 基准）；同页表头排序按钮、筛选卡内 icon 按钮按 40px 触控标准复核。
3. **横向滚动提示**：横向滚动容器（账龄 1240px / 存货 880px / 指标树）在首屏可视列被截断时展示滚动提示（右下角 fade 指示或 `aria-label` 提示），降低"列被截断"的感知困惑；DataTable 可加"滚动查看更多列"的通用提示插槽。

## 4. 结论

- 移动端表格现状：sticky 表头 + 关键列冻结 + 限高双滚动已覆盖基本可用性，无阻断性问题。
- 卡式化仅对存货明细单页有价值，投入产出比低；账龄/指标树/汇总类不适合。
- **决策：Phase 5 前不实施全站卡式化**，仅当移动端使用数据（埋点/反馈）证明明细页横向滚动成为痛点时，再按本评估第 3 节优先做三项低成本改进。
- 本报告记录在案，作为范围治理依据，避免后续需求蔓延。
