## 发布规则

- 禁止在生产目录执行 `npm audit fix`，禁止使用 `npm audit fix --force`。
- 存在 critical，或存在“已有兼容修复”的 high 时，阻断正式发布。
- 上游暂无修复的 high 必须保留本文件中的记录，并确认输入大小限制、鉴权、同源代理和内容净化措施仍有效。
- 每月至少复查一次；发现兼容补丁后在独立开发分支升级，完整执行 `npm run verify` 与导入/导出回归，再进入发布流程。
- `package-lock.json` 必须随依赖变更提交，生产只允许 `npm ci`。

## 当前补偿控制

- Excel 导入在服务端执行类型、大小和业务结构校验，上传接口受鉴权和权限门控制。
- 当前为 Vite SPA，不启用 React Router RSC action，RSC 模式 CSRF 路径不可达。
- 当前不启用 TipTap Markdown 属性解析，也不提供接收任意 TipTap 扩展属性对象的接口。
- 富文本输出继续经过 DOMPurify；在上游修复发布前，不得新增允许任意 HTML、脚本 URL 或不受控 SVG 的入口。
- 前端 API 统一走同源 `/api/v1`，后端只信任回环代理，并清理逐跳代理头。
- 正式发布前执行 CI、全量加密备份、迁移、健康检查和冒烟验证。
