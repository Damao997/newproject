### 0.2 实施时修正的规范缺陷（重要）

规范 v1.0 的以下写法**照抄会导致部署失败**，落地版已修正，规范正文同步更新：

| # | 规范原文问题 | 后果 | 落地版做法 |
|---|-------------|------|-----------|
| 1 | `init-roles.sql` 在 `DO $$ ... $$` 内使用 `:'DB_APP_PASSWORD'` | psql 客户端变量不会插值进服务端 PL/pgSQL 代码块，**语法错误，业务账号创建失败** | 拆出 `init-roles.sh` 包装器，以 `psql -v app_password=...` 传参；SQL 内用 `format(%L)` 转义后 `EXECUTE` |
| 2 | `init-roles.sql` 末尾在顶层裸写 `RAISE NOTICE` | `RAISE` 仅存在于 PL/pgSQL，**顶层是语法错误，脚本中断** | 包进 `DO $do$` 块 |
| 3 | compose 中 postgres 未挂载 `backup_data`，但 `archive_command` 写 `/backup_data/wal/%f` | **WAL 归档 100% 失败**，PITR 能力形同虚设 | postgres 服务补挂 `backup_data`；`init-roles.sh` 预建 `wal/full/logs` 子目录并 `chown postgres` |
| 4 | compose 中 postgres 未注入 `DB_APP_PASSWORD` | initdb 脚本拿不到密码，**业务账号无法创建** | postgres 服务补该环境变量 |
| 5 | postgres `command:` 用 YAML 折叠块（`command: \|`） | 多行被拼成单个字符串传给容器，参数解析脆弱 | 改为 YAML 数组逐项声明 |
| 6 | 规范要求对 `token_blacklist` 回收 `DELETE`，但又要求定期清理过期记录 | 二者矛盾：应用账号无权删，清理任务必然失败 | 保持回收（应用不得删），清理下沉到 `backup.sh cleanup-blacklist`，由 `db-backup` 容器以超级用户每日执行 |
| 7 | 附录 B Dockerfile 执行 `npm prune --omit=dev` | 会删掉 `prisma` CLI 与 `tsx`，**容器内 `migrate:deploy` 与 `prisma:seed` 直接失败** | 刻意不 prune，并在 Dockerfile 注释说明取舍；如需瘦身应改用一次性 migrate 容器 |
| 8 | 根 `.gitignore` 的 `.env.*` 规则把 `.env.example` 一并忽略 | 编排层模板无法入库，交付时缺失 | 增加 `!.env.example` 例外 |

> 另：`init-roles.sql` 补充了规范未涉及但必要的 `REVOKE CREATE ON SCHEMA public`、`REVOKE ALL ON SCHEMA public FROM PUBLIC` —— 否则 PostgreSQL 15 之前的默认策略允许任意角色在 `public` 建表，"仅 DML"的约束会被绕过。

## 二、docker-compose.yml（完整配置）

```yaml
# docker-compose.yml
# 浙江壹品慧财年经营数据分析平台 — Docker 单机部署

version: '3.8'

services:
  # ═══════════════════════════════════════════════════════
  # PostgreSQL 数据库
  # ═══════════════════════════════════════════════════════
  postgres:
    image: postgres:15-alpine
    container_name: yipinhui-postgres
    restart: unless-stopped
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: ${DB_SUPER_PASSWORD}
      POSTGRES_DB: yipinhui
    volumes:
      - pg_data:/var/lib/postgresql/data
      - ./init-roles.sql:/docker-entrypoint-initdb.d/01-init-roles.sql
    ports:
      - "127.0.0.1:5432:5432"     # 仅本地访问，不暴露到公网
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d yipinhui"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s
    networks:
      - app-network
    # PostgreSQL 配置（备份相关）
    command: |
      postgres
      -c archive_mode=on
      -c archive_command='test ! -f /backup_data/wal/%f && cp %p /backup_data/wal/%f'
      -c wal_level=replica
      -c max_wal_senders=3

  # ═══════════════════════════════════════════════════════
  # 后端 API 服务
  # ═══════════════════════════════════════════════════════
  backend:
    build:
      context: ./server
      dockerfile: Dockerfile
    container_name: yipinhui-backend
    restart: unless-stopped
    environment:
      NODE_ENV: production
      PORT: 3001
      # 数据库连接（使用 yipinhui_app 业务账号）
      DATABASE_URL: postgresql://yipinhui_app:${DB_APP_PASSWORD}@postgres:5432/yipinhui
      # JWT 密钥
      JWT_SECRET: ${JWT_SECRET}
      JWT_REFRESH_SECRET: ${JWT_REFRESH_SECRET}
      # DeepSeek AI API
      DEEPSEEK_API_KEY: ${DEEPSEEK_API_KEY}
      DEEPSEEK_API_BASE: https://api.deepseek.com/v1
      # 前端 Origin（用于 CORS 白名单）
      FRONTEND_ORIGIN: ${FRONTEND_ORIGIN:-http://localhost}
    ports:
      - "127.0.0.1:3001:3001"
    depends_on:
      postgres:
        condition: service_healthy
    networks:
      - app-network
    healthcheck:
      test: ["CMD", "wget", "--no-verbose", "--tries=1", "--spider", "http://localhost:3001/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 15s

  # ═══════════════════════════════════════════════════════
  # 前端 Web 服务（Nginx 静态文件 + API 反向代理）
  # ═══════════════════════════════════════════════════════
  frontend:
    build:
      context: ./web
      dockerfile: Dockerfile
    container_name: yipinhui-frontend
    restart: unless-stopped
    ports:
      - "80:80"
    depends_on:
      - backend
    networks:
      - app-network
    healthcheck:
      test: ["CMD", "wget", "--no-verbose", "--tries=1", "--spider", "http://localhost/"]
      interval: 30s
      timeout: 5s
      retries: 3

  # ═══════════════════════════════════════════════════════
  # 数据库备份服务（定时 cron）
  # ═══════════════════════════════════════════════════════
  db-backup:
    image: postgres:15-alpine
    container_name: yipinhui-backup
    restart: unless-stopped
    environment:
      PGHOST: postgres
      PGUSER: postgres
      PGPASSWORD: ${DB_SUPER_PASSWORD}
      PGDATABASE: yipinhui
      BACKUP_ENCRYPTION_KEY: ${BACKUP_ENCRYPTION_KEY}
    volumes:
      - backup_data:/backup_data
      - ./backup.sh:/usr/local/bin/backup.sh:ro
    entrypoint: ["/bin/sh", "-c"]
    command: |
      "
      # 创建 crontab: 每日凌晨 2:00 执行全量备份
      echo '0 2 * * * /usr/local/bin/backup.sh full >> /backup_data/backup.log 2>&1' > /etc/crontabs/root;
      # 每小时 WAL 归档轮转
      echo '0 * * * * /usr/local/bin/backup.sh rotate >> /backup_data/backup.log 2>&1' >> /etc/crontabs/root;
      # 启动 crond 前台运行
      exec crond -f -l 2
      "
    depends_on:
      postgres:
        condition: service_healthy
    networks:
      - app-network

# ═══════════════════════════════════════════════════════
# Volumes
# ═══════════════════════════════════════════════════════
volumes:
  pg_data:
    driver: local
  backup_data:
    driver: local

# ═══════════════════════════════════════════════════════
# Networks
# ═══════════════════════════════════════════════════════
networks:
  app-network:
    driver: bridge
```

> **注意**: DATABASE_URL 使用业务账号 `yipinhui_app`（非超级用户）连接数据库。Prisma migration 由超级用户手动执行。

```nginx
            proxy_http_version 1.1;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

            proxy_connect_timeout 60s;
            proxy_send_timeout 120s;
            proxy_read_timeout 120s;
        }

        # ═══════════════════════════════════════════════════
        # 健康检查端点
        # 后端实际路径为顶层 /health（刻意不带 /api/v1 前缀：

        location = /health {
            proxy_pass http://backend/health;
            proxy_http_version 1.1;
            proxy_set_header Host $host;
            access_log off;
        }

        location = /api/v1/health {
            proxy_pass http://backend/health;   # 注意：重写到后端的 /health
            proxy_http_version 1.1;
            proxy_set_header Host $host;
            access_log off;  # 健康检查不记录访问日志

        # ═══════════════════════════════════════════════════
        # 安全策略: 禁止访问隐藏文件
        # ═══════════════════════════════════════════════════
        location ~ /\. {
            deny all;
            access_log off;
            log_not_found off;
        }
    }
}
```

**SSE 关键配置说明**:
- `proxy_buffering off`：必须，否则 nginx 默认缓冲导致 SSE 流式失效
- `proxy_cache off`：必须，防止缓存流式响应
- `proxy_read_timeout 300s`：长连接超时，AI 生成可能耗时较长
- `chunked_transfer_encoding on`：支持分块传输
- `X-Accel-Buffering: no`：告知客户端不缓冲

**Express 端 SSE 路由注意事项**:
- SSE 路由禁用 `compression` 中间件
- 响应头：`Content-Type: text/event-stream`、`Cache-Control: no-cache`、`Connection: keep-alive`

## 四、数据库初始化

### 4.1 init-roles.sql（完整实现）

```sql
-- ============================================================
-- init-roles.sql
-- 浙江壹品慧财年经营数据分析平台 — 数据库初始化脚本
-- 执行时机: PostgreSQL 容器首次启动时自动执行
-- 挂载路径: /docker-entrypoint-initdb.d/01-init-roles.sql
-- ============================================================

-- 1. 创建业务账号 yipinhui_app
DO $$
BEGIN
  IF NOT EXISTS (SELECT FROM pg_catalog.pg_roles WHERE rolname = 'yipinhui_app') THEN
    CREATE ROLE yipinhui_app WITH LOGIN PASSWORD :'DB_APP_PASSWORD';
    RAISE NOTICE '业务账号 yipinhui_app 创建成功';
  ELSE
    RAISE NOTICE '业务账号 yipinhui_app 已存在，跳过创建';
  END IF;
END $$;

-- 2. 授权数据库连接
GRANT CONNECT ON DATABASE yipinhui TO yipinhui_app;

-- 3. 授权 schema 使用
GRANT USAGE ON SCHEMA public TO yipinhui_app;

-- 4. 对所有现有表授予 DML 权限（SELECT/INSERT/UPDATE/DELETE）
--    不授予 DDL 权限（CREATE/ALTER/DROP/TRUNCATE）
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO yipinhui_app;

-- 5. 对所有现有序列授予使用权限
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO yipinhui_app;

-- 6. 对所有现有函数授予执行权限
GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA public TO yipinhui_app;

-- 7. audit_log 特殊权限: INSERT + SELECT only（不可 UPDATE/DELETE，防篡改）
--    注意: 此 REVOKE 必须在 audit_log 表创建后执行
--    如果 audit_log 表尚未创建（由 Prisma migration 创建），以下语句将在后续执行
DO $$
BEGIN
  IF EXISTS (SELECT FROM information_schema.tables WHERE table_name = 'audit_log') THEN
    REVOKE UPDATE, DELETE ON audit_log FROM yipinhui_app;
    RAISE NOTICE 'audit_log 防篡改权限设置完成 (仅 INSERT + SELECT)';
  ELSE
    RAISE NOTICE 'audit_log 表尚未创建，防篡改权限待 Prisma migration 后执行';
  END IF;
END $$;

-- 8. token_blacklist 特殊权限: INSERT + SELECT only
DO $$
BEGIN
  IF EXISTS (SELECT FROM information_schema.tables WHERE table_name = 'token_blacklist') THEN
    REVOKE UPDATE, DELETE ON token_blacklist FROM yipinhui_app;
    RAISE NOTICE 'token_blacklist 权限设置完成 (仅 INSERT + SELECT)';
  ELSE
    RAISE NOTICE 'token_blacklist 表尚未创建，权限待 Prisma migration 后执行';
  END IF;
END $$;

-- 9. 设置默认权限（对将来创建的表自动生效）
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO yipinhui_app;

ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT USAGE, SELECT ON SEQUENCES TO yipinhui_app;

ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT EXECUTE ON FUNCTIONS TO yipinhui_app;

-- 10. 验证权限配置
SELECT
  table_name,
  string_agg(privilege_type, ', ' ORDER BY privilege_type) AS granted_privileges
FROM information_schema.table_privileges
WHERE grantee = 'yipinhui_app'
  AND table_schema = 'public'
GROUP BY table_name
ORDER BY table_name;

RAISE NOTICE '========================================';
RAISE NOTICE '数据库初始化完成';
RAISE NOTICE '业务账号: yipinhui_app (DML only)';
RAISE NOTICE '========================================';
```

### 4.2 数据库账号权限矩阵

| 账号 | 用途 | 权限 |
|------|------|------|
| `postgres`（超级用户） | 仅 Prisma migration 初始化 | 全部（DDL + DML） |
| `yipinhui_app`（业务账号） | 应用连接 | **仅 DML**（SELECT/INSERT/UPDATE/DELETE），不授予 DDL |
| `yipinhui_app` 对 `audit_log` | 审计日志 | **仅 INSERT + SELECT**（不可 UPDATE/DELETE，不可篡改） |

|--------|------|

### 6.2 backup.sh 完整脚本

```bash
#!/bin/sh
# backup.sh
# 浙江壹品慧财年经营数据分析平台 — 数据库备份脚本
# 挂载路径: /usr/local/bin/backup.sh
# 由 db-backup 容器的 crond 定时调用

set -e

BACKUP_DIR="/backup_data"
FULL_DIR="${BACKUP_DIR}/full"
WAL_DIR="${BACKUP_DIR}/wal"
LOG_FILE="${BACKUP_DIR}/backup.log"
ENCRYPTION_KEY="${BACKUP_ENCRYPTION_KEY:-change_me}"

log() {
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] $1" | tee -a "${LOG_FILE}"
}

# ═══════════════════════════════════════════════════════
# 全量备份
# ═══════════════════════════════════════════════════════
do_full_backup() {
    TIMESTAMP=$(date '+%Y%m%d_%H%M%S')
    BACKUP_FILE="${FULL_DIR}/yipinhui_full_${TIMESTAMP}.sql"
    ENCRYPTED_FILE="${BACKUP_FILE}.enc"

    log "开始全量备份..."

    mkdir -p "${FULL_DIR}"

    # 执行 pg_dump
    PGPASSWORD="${PGPASSWORD}" pg_dump \
        -h "${PGHOST:-postgres}" \
        -U "${PGUSER:-postgres}" \
        -d "${PGDATABASE:-yipinhui}" \
        -F c \
        -v \
        -f "${BACKUP_FILE}" 2>&1 | tee -a "${LOG_FILE}"

    if [ $? -eq 0 ]; then
        log "pg_dump 完成: ${BACKUP_FILE}"

        # AES-256-CBC 加密
        openssl enc -aes-256-cbc \
            -salt \
            -pbkdf2 \
            -pass pass:"${ENCRYPTION_KEY}" \
            -in "${BACKUP_FILE}" \
            -out "${ENCRYPTED_FILE}"

        if [ $? -eq 0 ]; then
            log "加密完成: ${ENCRYPTED_FILE}"
            # 加密成功后删除原始文件
            rm -f "${BACKUP_FILE}"
        else
            log "加密失败，保留原始备份文件"
        fi
    else
        log "全量备份失败!"
        return 1
    fi

    log "全量备份结束"
}

# ═══════════════════════════════════════════════════════
# 清理过期备份
# ═══════════════════════════════════════════════════════
do_rotate() {
    log "开始备份轮转..."

    # 清理 30 天前的全量备份
    if [ -d "${FULL_DIR}" ]; then
        DELETED_FULL=$(find "${FULL_DIR}" -name "*.enc" -type f -mtime +30 -delete -print | wc -l)
        log "清理全量备份: ${DELETED_FULL} 个文件 (保留 30 天)"
    fi

    # 清理 7 天前的 WAL 归档
    if [ -d "${WAL_DIR}" ]; then
        DELETED_WAL=$(find "${WAL_DIR}" -type f -mtime +7 -delete -print | wc -l)
        log "清理 WAL 归档: ${DELETED_WAL} 个文件 (保留 7 天)"
    fi

    log "备份轮转结束"
}

# ═══════════════════════════════════════════════════════
# 恢复测试（每季度手动执行）
# ═══════════════════════════════════════════════════════
do_restore_test() {
    log "开始恢复演练..."

    LATEST_BACKUP=$(ls -t "${FULL_DIR}"/*.enc 2>/dev/null | head -1)
    if [ -z "${LATEST_BACKUP}" ]; then
        log "无可用备份，演练取消"
        return 1
    fi

    DECRYPTED_FILE="${LATEST_BACKUP%.enc}.restore_test.sql"
    log "解密测试: ${LATEST_BACKUP}"

    # 解密
    openssl enc -aes-256-cbc -d \
        -pbkdf2 \
        -pass pass:"${ENCRYPTION_KEY}" \
        -in "${LATEST_BACKUP}" \
        -out "${DECRYPTED_FILE}" 2>&1

    if [ $? -eq 0 ]; then
        log "解密成功: ${DECRYPTED_FILE}"

        # 验证文件完整性（检查文件大小 > 0）
        SIZE=$(stat -c%s "${DECRYPTED_FILE}" 2>/dev/null || echo 0)
        if [ "${SIZE}" -gt 0 ]; then
            log "备份文件完整性验证通过 (大小: ${SIZE} bytes)"
        else
            log "备份文件大小为 0，可能损坏!"
            return 1
        fi

        # 清理测试文件
        rm -f "${DECRYPTED_FILE}"
    else
        log "解密失败!"
        return 1
    fi

    log "恢复演练结束"
}

# ═══════════════════════════════════════════════════════
# 主入口
# ═══════════════════════════════════════════════════════
case "${1}" in
    full)
        do_full_backup
        ;;
    rotate)
        do_rotate
        ;;
    restore-test)
        do_restore_test
        ;;
    *)
        echo "用法: $0 {full|rotate|restore-test}"
        echo "  full         - 执行全量备份 + 加密"
        echo "  rotate       - 清理过期备份 (30天全量 / 7天WAL)"
        echo "  restore-test - 恢复演练 (解密最新备份并验证完整性)"
        exit 1
        ;;
esac
```

### 6.3 恢复演练清单

每季度执行一次恢复演练，记录结果：

| # | 步骤 | 命令 | 预期结果 |
|---|------|------|----------|
| 1 | 列出可用备份 | `ls -la /backup_data/full/` | 最近 30 天内有备份文件 |
| 2 | 解密最新备份 | `docker exec yipinhui-backup backup.sh restore-test` | 解密成功，完整性验证通过 |
| 3 | 创建恢复测试库 | `createdb -U postgres yipinhui_restore_test` | 数据库创建成功 |
| 4 | 导入备份 | `pg_restore -d yipinhui_restore_test <backup_file>` | 数据导入成功 |
| 5 | 验证关键表 | `SELECT count(*) FROM company;` 等 | 行数与生产一致 |
| 6 | 清理测试库 | `dropdb -U postgres yipinhui_restore_test` | 清理成功 |

### 附录 H: 发版前检查清单（生产数据持久化保障，v1.2 新增）

> **适用**：每次新版本发布（`deploy-zjyph.ps1` / Docker 标准流程）。
> **目的**：确保生产环境手动修改的数据（科目/公司/汇总映射等）在发版后保持不变。
> **已核实机制**：正常发版流程**不执行** `prisma:seed`（`prisma migrate deploy` 不触发 seed；应用启动 [server.ts](../README.md) 无初始化逻辑）；`server/scripts/migrate-subject-codes.ts` 为手动运维工具，不会被部署自动调用。

发版前逐项核对：

1. **审查新增迁移的 DML**：检查本版本 `server/prisma/migrations/` 下新增迁移的 `migration.sql` 是否含 `INSERT / UPDATE / DELETE / TRUNCATE / COPY`。若含 DML，须逐条确认幂等性（可重复执行结果一致）与对生产手动数据的覆盖范围，并在变更记录中登记覆盖对象。`prisma migrate deploy` 只执行未应用的迁移，已应用迁移不会重放。
2. **确认发版流程无 seed 步骤**：核对 `deploy-zjyph.ps1`（步骤 0-6）与 Docker 发布流程，确保不包含 `prisma:seed` / `setup`。生产库种子数据仅在**首次部署**（空库）时导入一次；后续任何版本一律不执行 seed。`prisma migrate deploy` 不会触发 seed（仅 `migrate dev` / `migrate reset` / `db seed` 触发）。
3. **seed 生产防护生效**：确认 `server/prisma/seed.ts` 已包含 `NODE_ENV=production` 拒绝执行防护（`ALLOW_SEED_IN_PROD=1` 逃生开关）。误执行 seed 时进程应以非 0 退出码拒绝，且不产生任何数据库写入。
4. **手动数据变更台账**：生产手动修改（科目编码/名称/层级/科目类型、公司编码/名称/类型/排序、汇总映射、主体展示配置等）应登记为 JSON 台账（格式见 `server/scripts/verify-prod-manual-data.ts` 文件头），随版本发布同步更新。
5. **发版后核对**：发布完成后执行 `npx tsx server/scripts/verify-prod-manual-data.ts --ledger <台账路径>`（只读，不写库），逐项比对台账与生产库，确认无差异后发布完成。
