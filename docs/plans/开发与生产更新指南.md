# 开发与生产更新指南

## 1. 固定目录职责

| 目录 | 用途 | 允许操作 |
|---|---|---|
| `D:\ZJYPHFA-dev` | 开发工作区 | 拉取、建分支、编码、测试、提交、推送、创建 PR |
| `D:\ZJYPHFA` | 生产工作区 | 获取 tag、备份、部署、巡检、回滚 |

生产目录不得再承担开发职责。`data/`、`backup/`、`tools/`、`frp/`、`recovery-*/`、真实 `.env` 和运维面板真实配置只存在于生产目录。

生产目录禁止执行 `git stash`，尤其是 `git stash -u` 和 `git stash -a`：前者会搬走未跟踪运行数据，后者连已忽略的数据也会搬走。生产工作区不干净时，停止发布并在开发工作区处理，不得就地 stash。

## 2. 日常开发更新

```powershell
cd D:\ZJYPHFA-dev
git fetch origin --prune
git switch develop
git pull --ff-only origin develop
git switch -c feat/<简短名称>
```

修改完成后：

```powershell
npm run verify
git status --short
git add <明确的文件列表>
git commit -m "feat: 简体中文说明"
git push -u origin feat/<简短名称>
```

通过 PR 合入 `develop`。不得执行 `git add .`，防止把现场文件误加入提交。所有 stash 只能在 `D:\ZJYPHFA-dev` 使用。

## 3. 正式发布

1. 在开发工作区更新 `web/public/release-notes.json`。
2. 通过 PR 将 `develop` 合入 `main`，等待 CI 全部通过。
3. 在干净的开发工作区为 main 创建带注释 tag：

```powershell
cd D:\ZJYPHFA-dev
git fetch origin --prune
git switch main
git pull --ff-only origin main
git status --short
git tag -a v2026.09.2 -m "release: v2026.09.2"
git push origin v2026.09.2
```

4. 在生产目录执行唯一部署入口：

```powershell
cd D:\ZJYPHFA
powershell -NoProfile -ExecutionPolicy Bypass -File server\scripts\deploy-zjyph.ps1 -Tag v2026.09.2
```

部署脚本会验证 tag 确实属于 `origin/main`，先创建并校验数据库备份，再检出 tag、安装依赖，并把前端构建到 `web/.release/` 隔离目录；迁移成功后才切换静态产物、重载 PM2、执行健康检查和冒烟验证。正式发布不要使用 `-AllowUntagged`、`-SkipBackup` 或 `-SkipSmoke`。

若部署在切换静态产物后失败，不要继续手工覆盖文件。旧前端产物会保留在 `web/.release/dist-previous`，先记录错误并按上一正式 tag 重新运行部署；数据库迁移是否可回滚仍以该版本的迁移说明为准。

## 4. 生产紧急修复

从 `main` 创建 `hotfix/*` 分支，在开发目录修复并验证；通过 PR 合入 `main` 后打新 tag。修复还必须回合 `develop`，避免下次发布回退。

## 5. 回滚

代码回滚仍使用正式 tag：

```powershell
cd D:\ZJYPHFA
powershell -NoProfile -ExecutionPolicy Bypass -File server\scripts\deploy-zjyph.ps1 -Tag <上一稳定版本>
```

若迁移包含不可逆数据变化，先按发布记录执行数据库恢复方案；禁止仅回退代码后继续运行。

## 6. 每周检查

```powershell
cd D:\ZJYPHFA
powershell -NoProfile -ExecutionPolicy Bypass -File server\scripts\ops-check-zjyph.ps1
```

同时确认：最近备份不超过 30 小时、生产工作区没有已跟踪文件改动、当前 HEAD 精确匹配正式 tag。

依赖风险按 `docs/plans/依赖安全基线.md` 每月复查；不要在生产目录直接执行自动修复。
