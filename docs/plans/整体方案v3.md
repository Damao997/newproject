## 一、方案概述

### 1.1 项目身份

| 项 | 内容 |
|----|------|
| **项目名** | `yipinhui_finance_analytics`（浙江壹品慧财年经营数据分析 Web 平台） |
| **产品本质** | "Excel 进、看板/报表出"的内部管理口径财务数据平台 |
| **口径属性** | 内部管理口径（非审计/法定财报口径），强调灵活、可解释、可追溯 |
| **目标用户** | 财务分析师（兼IT管理员）、经营层、事业部负责人、财务人员 |
| **核心目标** | 降低可视化门槛、统一管理口径、提升决策时效、保障可追溯、灵活可导出 |
| **单位主体** | 单主体、人民币、简体中文（MVP 不支持国际化） |
| **部署** | 内网私有化 Docker 单机部署（需防火墙放行 DeepSeek API 域名） |

### 2.5 Resource 编码规范（三段式）

所有权限校验基于三段式 `模块:子页面:操作` 编码：

| 层级 | 格式 | 示例 |
|------|------|------|
| **模块级** | `{module}` | `data`、`indicators`、`admin` |
| **页面级** | `{module}:{page}` | `data:import`、`admin:users` |
| **按钮级** | `{module}:{page}:{button}` | `data:import:upload`、`admin:users:reset-password` |

**action 枚举**：`view` / `create` / `update` / `delete` / `export` / `import`

**模块级编码前缀**：

| 模块 | resource 前缀 | 典型按钮级 resource |
|------|--------------|---------------------|
| 登录页 | `auth` | `auth:login`（公开路由） |
| 首页看板 | `dashboard` | `dashboard:view`、`dashboard:export` |
| 财务指标 | `indicators` | `indicators:view`、`indicators:export` |
| 往来分析 | `transactions` | `transactions:view`、`transactions:import` |
| 存货管理 | `inventory` | `inventory:view`、`inventory:export`（**资源码已预留，后端端点未实现**） |
| 分析报告 | `reports` | `reports:view`、`reports:create` |
| 其他工具 | `tools` | `tools:view`（企业工商信息查询；已在 seed 授予 admin / finance_manager / finance_analyst_it） |
| 数据管理 | `data` | `data:browse:view`、`data:import:upload`、`data:metric:create` |
| 权限管理 | `admin` | `admin:users:view`、`admin:roles:delete` |

> AI 路由（`/api/v1/ai/*`）不单设模块前缀，**复用**既有编码：润色/分析/概述用 `reports:create`，公式生成/检测用 `data:metric:create`。


> 完整 resource 编码清单（含按钮级全部编码）见 `CLAUDE.md` 或 `安全与权限规范.md`。

## 三、技术架构

### 3.1 关键技术决策

**UI 组件方案：Radix UI + Shadcn/ui + Ant Design 5（仅 ProTable）**

| # | 理由 |
|---|------|
| 1 | **表格能力保留**：财务后台大量复杂表格（往来客商明细、账龄矩阵、交叉报表），Ant Design 5 ProTable 的虚拟滚动、固定列、可编辑单元格等能力不可替代 |
| 2 | **轻量化**：Ant Design 全量 ~120KB（gzip），仅保留 ProTable ~20KB。其余组件用 Shadcn/ui（Button/Card/Dialog/Tabs 等），基于 Radix UI headless + Tailwind，更轻、更可控 |
| 3 | **样式可控**：Shadcn/ui 源码直接复制到项目中，可随意修改，不像 AntD 需要复杂 Token 覆盖。Tailwind 原子类直接对应 Design Token |
| 4 | **企业级中文本地化**：ProTable 默认中文、日期选择器、金额格式化、表单校验提示更贴合国内财务场景。色标方向固定为 cn（红涨绿跌） |
| 5 | **P0 仅亮主题**：暗色模式延后至 P2，减少初期 2-3 人日投入 |

**数据库：PostgreSQL 15+（非 SQLite）**

| # | 理由 |
|---|------|
| 1 | **递归 CTE**：汇总映射需要递归查询（WITH RECURSIVE），PostgreSQL 原生支持且性能优异 |
| 2 | **JSON 查询**：PostgreSQL 的 `->>`/`->` 操作符原生支持 JSON 字段查询 |
| 3 | **连接池**：PostgreSQL 支持并发连接池，适合多用户场景 |
| 4 | **按月分区**：audit_log 按月分区（PARTITION BY RANGE），满足金融合规 5 年留存需求 |
| 5 | **Docker 部署成本极低**：docker-compose 增加一个 postgres:15-alpine 容器即可 |

### 3.4 中间件执行链（全局链 + 路由级链）

实现见 `server/src/app.ts`（全局装配）与 `server/src/routes/*.ts`（路由级装饰）。

**全局链**（`app.use`，对所有请求生效）：

```
请求进入
  │
  ▼
1. trace-id.ts      → 生成/透传 traceId（UUID v4），贯穿日志、审计与统一响应
  │
  ▼
2. 访问日志          → 记录 method/url/status/user/ip/耗时（res 'finish' 时输出）
  │
  ▼
3. helmet.ts        → HTTP 安全头（CSP/HSTS 1年/X-Frame-Options/X-Content-Type-Options）
  │
  ▼
4. cors.ts          → 跨域校验（仅允许 FRONTEND_ORIGIN 白名单，支持逗号分隔多值，严禁通配符）
  │
  ▼
5. express.json()   → 请求体解析（limit: 1mb）
  │
  ▼
6. rate-limit.ts    → 通用限流 100 次/分钟，仅作用于 /api/v1 前缀
  │                    └─ /health 在此之前注册，不经限流
  ▼
路由分发 → 404 兜底（notFoundHandler）→ 全局错误处理（errorHandler）
```

**路由级链**（在各路由文件内按端点叠加，`Router` 级或单端点级）：

```
7.  auth.ts          → JWT 验证（access token 校验 + 黑名单校验）
  │                    └─ 公开端点不挂载：/auth/login、/auth/refresh、/health、GET /reports/shared/:token
  ▼
8.  permission.ts    → requirePermission(resource, action)，默认拒绝（无匹配 permission 记录 → 403 且补记审计）
  │
  ▼
9.  scope.ts         → 数据范围注入（Prisma $extends 自动拦截读操作 + $queryRaw 手动注入）
  │                    └─ 优先级：data_scope_codes > company_code > org_scope_bu > scope_value='*'，兜底 none
  ▼
10. softDelete.ts    → 软删除过滤（Prisma extension 自动注入 status='active'）
  │
  ▼
11. audit.ts         → 审计记录（核心操作异步写入 audit_log，仅 INSERT，detail 不记录金额与 PII）
  │
  ▼
路由处理函数 → Service → Prisma → PostgreSQL
```

> **为何鉴权不做全局链**：登录、刷新、健康检查、分享链接访问均为公开端点，若把 `authenticate`/`requirePermission` 置于全局会误拦；放在路由级还能让"端点 ↔ 所需权限"在同一行可读，便于评审与审计。

> 各中间件详细实现代码见 `安全与权限规范.md`。

## 四、数据模型总览

### 4.1 设计原则

| 原则 | 说明 |
|------|------|
| **三大范式** | 1NF 字段原子化 / 2NF 消除部分依赖 / 3NF 消除传递依赖；允许有明确业务场景+严格评估的反范式例外 |
| **长表设计** | 事实表采用长表（一行一指标一值），xlsx 宽表在导入时由后端 ImportService 执行 unpivot/melt |
| **三张事实表分离** | 经营数据、静态数据、年度预算来自 3 个不同 xlsx，期间维度体系不同（经营 5 个 vs 静态 4 个），分表消除传递依赖 |
| **软删除** | 所有标记 `status` 字段的表（company、account_subject、counterparty、user 等），通过 Prisma 扩展层统一注入 `status='active'` 过滤 |
| **编码前缀识别** | 公司编码：单体 `CO`+6 位数字 / 汇总 `SUM`+4 位数字；科目编码：经营 `OP_xxx` / 静态 `ST_xxx`；计算类指标：`CALC_`+业务名。前缀使程序可直接识别类型，无需查表 |

### 4.2 实体关系总览（文字描述）

核心关系链：

```

  ├── fact_operating（经营事实，复合键: 公司+科目+期间+期间维度+批次）
```

### 4.4 宽表到长表转换策略（7 步流程）

1. **前端预览**：SheetJS `read(data, { sheetRows: 100 })` 仅首 100 行预览，原始文件 FormData 上传
2. **后端接收**：multer 接收，fileFilter 仅 .xlsx/.xls，fileSize ≤ 50MB，校验 MIME magic number
3. **流式解析**：SheetJS/ExcelJS 读取，按 mapping_scheme.column_map 识别维度列与值列
4. **Zod 校验**：校验逻辑收敛到后端单一实现（消除前后端双层校验冗余）
5. **行级 unpivot**：遍历值列，每列生成一条长表记录（1 宽行 → N 长行）
6. **编码转换**：公司名→CO 编码、列名→OP/ST 科目编码（通过 MappingScheme 映射）
7. **事务落库**：批量 INSERT（事务+批量优化），返回标准化结果 {batchId, successCount, errorCount, errors}

> 详细的 column_map JSON 结构、多级表头处理、静态数据特殊解析逻辑见 `数据模型规范.md`。

### 5.2 看板渲染流程（含 DAG + scope + 越权防护）

```
前端请求 GET /indicators/operating?company=&period=
  → auth.ts（JWT 验证）
  → permission.ts（indicators:view 权限校验）
  → scope.ts（Prisma extension 自动注入 company_code 过滤）
  → softDelete.ts（status='active' 过滤）
  → [若选汇总主体] P0-S5 越权防护：递归 CTE 列出公司 ∩ 用户 scope 取交集，空集返回 403
  → 查询 active 批次事实数据
  → AggregationService:
      a. 聚合 data 类指标（直接从 Fact 表）
      b. 构建 calc 指标依赖 DAG（从 metric.depends_on）
      c. 拓扑排序 + 环检测（发现环报错 METRIC_CIRCULAR_REF）
      d. 按拓扑序计算 calc 指标（formula 解析，白名单算子仅 +-*/）
  → IndicatorsService 计算同比/环比/预算达成率
  → 返回表格数据 → 前端渲染 Ant Design Table
```

### 5.3 报告生成流程（P2，摘要）

```
选模板 → 创建 report（draft）→ TipTap 分模块编辑
  → 数据自动填充（AggregationService 拉取指标值 → section.auto_data）
  → 手工录入分析文字（DOMPurify 净化存储）
  → AI 润色（polish）: 选中文本 → 脱敏 → DeepSeek SSE → 预览 → 确认替换
  → AI 追加分析（analyze）: 结构化指标 → 计算变化率 → 分层脱敏 → 事实约束注入 → DeepSeek SSE → 返回
  → 组装（目录/页码/表头）→ 导出 Word/PDF → 版本快照
  → 分享链接: UUID v4 + 登录校验 + scope 校验 + 可选有效期（7天/30天/永久）
```

### 5.4 汇总聚合流程（含 scope 交集防护）

```
用户选汇总主体（如"华东区汇总"SUM0002）
  → 递归 CTE 查 company_aggregation_map（depth 计数器 + LIMIT 20 防无限递归）
  → CTE 查出的公司列表 ∩ 用户 scope 公司列表 = INTERSECTION
  → INTERSECTION 为空 → 403 "您无权限查看该汇总主体的数据"
  → INTERSECTION 非空 → 以 INTERSECTION 为公司范围查询 fact 表 → 聚合求和
  → 内部抵消: 若选择"剔除内部"则过滤 is_internal_elimination=true 的映射
```

### 5.5 AI 润色流程（P2，双管道分离）

**Polish 管道（润色）**：用户选中文本 → Prompt 注入防护（四层）→ 扫描公司名/金额 → 动态脱敏（公司名→代号，金额→区间）→ 构建脱敏 prompt → DeepSeek API SSE 流式 → LLM 输出过滤 → 反向还原（代号→原始公司名）→ 前端侧边栏流式预览 → 用户确认后替换原文

**Analyze 管道（追加分析）**：结构化指标数据 → Prompt 注入防护 → 计算变化率 → 分层脱敏（变化率不脱敏 / 绝对金额→区间 / 公司名→代号）→ 事实约束注入（关键变化率作为 prompt 约束）→ DeepSeek API SSE → LLM 输出过滤 → 返回新文本（ai_suggested=true + 免责声明）

> 完整的脱敏规则、双管道架构、Prompt 注入防护四层机制、频率限制、AI 生成内容标识见 `AI模块规范.md`。

### 5.6 审计中间件流程

```
请求 → auth→permission → 路由处理函数执行
  → audit.ts 后置记录（异步，不阻塞响应）:
      判断操作类型 → 认证/数据变更/导出分享/权限变更 → 写入 audit_log
      detail 仅记录元信息（操作类型/目标ID/字段名），不记录原始金额
      应用账号仅 INSERT 权限（不可 UPDATE/DELETE）
      写入失败不阻塞主流程，仅记录错误日志
```

## 六、API 设计总览

### 6.1 统一规范

- **协议**：RESTful，`/api/v1/<resource>`
- **统一响应**：`{ code: 0, data: <>, message: "" }`
- **认证**：JWT Bearer Token（access 15min + refresh 7day + 轮转）
- **权限**：所有非公开路由声明 `requirePermission(resource, action)`，默认拒绝

### 6.2 JWT 认证流程

```
登录成功 → 签发 access_token(15min) + refresh_token(7day)
请求 API → auth.ts 验证 access_token
access_token 过期 → 前端用 refresh_token 调 /auth/refresh
  → 后端校验 jti 不在 token_blacklist 表
  → 旧 jti 写入 token_blacklist（轮转失效）
  → 签发新 access_token + 新 refresh_token
登出 → /auth/logout 将 refresh_token jti 写入 token_blacklist（持久化，重启不丢失）
定期清理 → 定时任务清理 token_blacklist 中 expired_at < NOW() 的记录
```

| 6 | 数据库 | PostgreSQL 15+（递归 CTE + JSON + 分区表） |
| 7 | AI 引擎 | DeepSeek API 直连（OpenAI 兼容接口，SSE 流式；数据出内网，脱敏强制） |

### 8.2 数据模型决策

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 存储格式 | FactRecord 长表（聚合灵活、下钻友好、符合 3NF） |
| 2 | 事实表拆分 | 三张（经营/静态/预算），期间维度体系不同 |
| 3 | 宽表→长表 | 后端 ImportService unpivot（前端仅预览首 100 行） |
| 4 | 科目体系 | account_subject 统一表（152+34=186 项） |
| 5 | 编码规则 | 公司 CO/SUM 前缀 + 科目 OP/ST 前缀 + 计算指标 CALC_ 前缀 |
| 6 | 内部抵消 | company_aggregation_map.is_internal_elimination + counterparty.is_internal |
| 7 | 批次生命周期 | draft→active→archived→purged，新批次激活自动归档旧批次 |
| 8 | 环检测 | 写入时 BFS/DFS 检测汇总映射环；计算时 DAG 拓扑排序检测指标环 |
| 9 | 反范式例外 | transaction_detail.closing_balance 等高频查询字段允许冗余，需在 schema 注释中标注 |

### 8.3 权限与安全决策

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 预置角色 | 5 个（管理员/财务主管/部门经理/查看者/财务分析师兼IT） |
| 2 | 权限矩阵 | 8 模块 x 6 操作 x 5 角色 = 240 权限点 |
| 3 | resource 编码 | 三段式 `模块:子页面:操作` |
| 4 | 权限校验 | permission.ts 统一中间件 + 默认拒绝 |
| 5 | scope 实现 | Prisma extension（$extends）自动拦截 + $queryRaw 手动注入 |
| 6 | 汇总越权 | 递归 CTE 结果与用户 scope 取交集，空集返回 403 |
| 7 | 审计日志 | 核心操作 P0（认证/数据变更/导出/权限变更）+ 按月分区 + 仅 INSERT+SELECT + 留存 5 年 |
| 8 | company_code/org_scope_bu | company_code 精确绑定优先 |
| 9 | 分享链接 | UUID v4 + 登录校验 + 权限校验 + 可选有效期（7天/30天/永久） |
| 10 | JWT 黑名单 | PostgreSQL token_blacklist 表持久化（服务重启不丢失） |
| 11 | refresh token | 轮转机制（刷新后旧 token 失效，泄露后仅可用一次） |
| 12 | DB 账号 | yipinhui_app 仅 DML，audit_log 仅 INSERT+SELECT |
| 13 | Web 安全 | helmet（CSP/HSTS/X-Frame-Options）+ cors（仅前端 origin） |
| 14 | 备份 | 每日全量 + WAL 归档 + 加密 + 保留 30 天 + 季度恢复演练 |
| 15 | 文件上传安全 | multer fileFilter 仅 .xlsx/.xls + fileSize 50MB + MIME magic number 校验 |
