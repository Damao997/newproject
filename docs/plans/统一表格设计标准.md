# 统一表格设计标准 v1.0

> 定位：全站数据表格的唯一设计基准（与 `docs/plans/frontend-design-proposal.md` §4.4 同源，本文件为可执行细则）。
> 适用：web 前端所有业务表格；新增页面表格一律按本标准实现。

---

## 1. 背景与目标

历史表格实现存在 3 套体系 + 约 20 处手写原生 `<table>`，字号、表头、密度、边框各成一套，且大数据模式（>100 行）与轻量模式存在交互断档。本标准以 `DataTable` 为唯一基础表格组件，统一设计令牌与交互能力，消除重复实现。

## 2. 现状全景（2026-08 梳理结论）

### 组件层（`web/src/components/data-table/`）

| 组件 | 职责 | 说明 |

## 3. 统一设计令牌（权威基准）

```
容器（全站统一卡片化）：
- 边框：1px solid hsl(var(--border))
- 圆角：8px（rounded-card）
- 卡头：区块标题/统计信息置于 border-b 行（px-4 py-2.5）

表头：
- 背景：bg-muted/50
- 字体：13px / 500（text-[13px] font-medium）
- 颜色：text-black
- 内边距：h-11 + px-4（紧凑 h-8）
- 对齐：一律居中（含金额列表头、排序表头）

行：
- 字体：13px
- 内边距：p-4（dense px-4 py-1.5 / compact px-3 py-2）
- 边框：顶部 1px solid hsl(var(--border))
- hover：bg-muted/50，transition background 0.15s

数值列：
- 明细/交叉宽表：右对齐 + font-num（等宽数字，纵向对齐）
- 对比型表格（指标树/覆盖率矩阵）：居中 + font-num
- 金额千分位 2 位小数（formatMoneyWan，单位"万"独立小字后缀）
- 数量千分位整数（formatQuantity）；比率百分比 1 位小数（formatPercent）

密度三档（DataTable density 属性）：
- default：表头 h-11 / 单元格 p-4
- dense：表头 h-8 / 单元格 px-4 py-1.5
- compact：表头 h-8 / 单元格 px-3 py-2

状态与无障碍：
- 空态：文案（可带引导动作），td role="status"
- 加载态：骨架行（.skeleton shimmer，DataTable loading 属性）
- th scope="col"；排序列 aria-sort；checkbox 一律 aria-label
- 冻结列：sticky left-0 + 不透明背景 + 右侧分隔线
- 限高滚动：maxHeight + sticky 表头（bg-muted 不透明）
```

**禁止**：raw hex 色值、Tailwind 调色板类（红/蓝/绿原色）、表头灰色小字（text-xs text-muted-foreground 左对齐样式已废弃）。

## 4. 组件使用规范

### 4.1 选择哪个组件

| 场景 | 使用 |
|------|------|
| 行数可控（<100）的列表/明细/配置表 | `DataTable` |
| 数据量可能超过 100 行 | `ProDataTable`（自动切换虚拟滚动） |
| 双层表头/rowSpan/colSpan 合并矩阵 | 手写（参照豁免项样式） |
| 分页 | `Pagination`（独立于表格，放表格卡底部 border-t 行） |

### 4.2 DataTable API（v1.0）

```tsx
<DataTable
  columns={columns}                 // DataTableColumn<T>[]：key/header/align/cellClassName/headerClassName/render/sticky/sortable
  data={rows}
  rowKey={(r) => r.id}
  density="compact"                 // default | dense | compact（dense 布尔兼容旧用法）
  maxHeight="320px"                 // 限高滚动 + sticky 表头
  loading={isLoading}               // 骨架行
  onRowClick={...}                  // 行点击（配合 rowClassName 高亮）
  rowClassName={...}                // 斑马纹/选中态/警示行背景
  sortKey={...} sortDirection={...} onSortChange={...}  // 受控排序（三态循环 asc→desc→null）
  footer={<tr>...</tr>}             // 合计行
  caption="表格标题"                 // 屏幕阅读器
/>
```

### 4.3 列定义要点

- 数值列：`align: 'right'` + `cellClassName: 'font-num'`
- 状态列：`Badge`（语义变体，禁 hex）
- 操作列：`align: 'right'`（或 center）+ ghost 按钮组，权限门禁在 render 内
- 响应式隐藏列：`headerClassName: 'hidden md:table-cell'` + `cellClassName: 'hidden md:table-cell'`（sm/md 断点）
- 长文本截断：render 内 `<span className="block max-w-[160px] truncate" title={...}>`

### 4.4 大数据模式（ProDataTable）

能力已对齐 DataTable（阈值切换不断档）：sticky → fixed、cellClassName → className、headerClassName → onHeaderCell、density → size、maxHeight → scroll.y（支持 px/vh 解析）、sortable → sorter（三态循环）、onRowClick/rowClassName/loading 透传。**禁止**在除 `pro-table-inner.tsx` 外引用 antd（规范 §2.1）。

## 6. 方案 B 评估：@tanstack/react-virtual 自研虚拟滚动（暂不实施）

### 6.1 架构设计

- 新组件 `data-table/virtual-table.tsx`：基于 `@tanstack/react-virtual`（约 15KB gzip）替换 `pro-table-inner.tsx`
- 删除依赖：`antd` + `@ant-design/pro-table`（约 120KB+ gzip 懒加载 chunk）
- 样式 100% 走 Tailwind 语义令牌，删除 THEME_HEX/THEME_PRESETS 主题镜像（消灭主题双轨）
- 排序/aria-sort 与 DataTable 同源实现（compareRaw 复用）

### 6.2 关键技术点

| 难点 | 方案 |
|------|------|
| 虚拟化 × sticky 表头 | 表头独立于虚拟窗口渲染，行容器内滚动 |
| 虚拟化 × 冻结列 | 冻结列单独渲染 + 滚动同步（translateX），或采用 antd 同款"固定列双表"方案 |
| 动态行高（展开行） | useVirtualizer `estimateSize` + 行高缓存（展开时 measureElement） |
| 横向滚动同步 | 滚动容器统一监听，冻结列 translateX 跟随 |
| 键盘导航 | 虚拟窗口外处理焦点，避免滚动跳变 |

### 6.3 决策触发条件

- 暗色主题成为硬需求（当前 THEME_HEX 镜像需人工同步，双轨维护成本高）
- 指标页大数据加载体感问题（懒加载 chunk 下载耗时）
- 需要动态行高虚拟化或自定义滚动容器
- 启动前需完整回归 9 个 DataTable 使用点 + 阈值切换逻辑

### 6.4 结论

维持 antd ProTable（方案 A）为本期基线：改动小、风险低、虚拟滚动经过大规模生产验证。方案 B 收益明确（体积/主题/能力统一）但工作量 2-3 倍，作为下一阶段候选，触发条件满足时再启动。
