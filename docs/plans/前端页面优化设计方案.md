# 财年经营数据分析平台 · Web 前端优化设计方案

> 审查日期：2026-08-25
> 审查范围：`web/src` 全部 7 大模块 30+ 路由页面（首页看板 / 财务指标 / 往来分析 / 存货管理 / 分析报告 / 数据管理 / 权限管理）及布局、表格、图表组件体系
> 审查方式：全量代码遍历 + 设计系统一致性核对

## 一、总体评价（实测事实）

前端基础成熟度高于一般内部系统：

- **设计令牌体系完整**：HSL CSS 变量 + 三套侧边栏主题（浅色 / 深紫渐变 / 深色）+ 财务红涨绿跌约定（`finance-red` / `finance-green`），见 `web/src/styles/globals.css`；
- **页面骨架统一**：`PageContainer`（`web/src/components/layout/page-container.tsx`）承担标题区 / actions / 吸顶 / 全宽筛选布局，全站一致；
- **表格体系规范**：`DataTable`（`web/src/components/data-table/data-table.tsx`）支持密度三档、冻结列（左/右）、受控排序（aria-sort）、骨架行、行选择、列宽拖拽，对齐《统一表格设计标准》；
- **三态完备**：看板加载（骨架屏）/ 错误（重试卡）/ 空态（引导卡）齐备；
- **状态持久化与深链**：筛选条件经 `pageStateStore` 持久化，旧 `?tab=` URL 兼容重定向、看板→明细页深链参数均落地；
- **无障碍意识良好**：`aria-sort`、`aria-label`、`prefers-reduced-motion` 降级、屏幕阅读器专用 caption 等。

**本方案聚焦"长尾不一致"的收敛，而非重构。**

## 三、优化设计方案

### 方向 1 · 交互反馈收敛为「一弹窗一提示」体系（对应 P0-1）

- **确认类**：全部原生 `confirm/alert` 迁移到现有 `useConfirm`（`web/src/components/ui/confirm-dialog.tsx`）：
  - 停用/删除用户 → `danger: true` 红色确认按钮；
  - 物理删除用户 → `requireInput: 用户名` 输入防呆；
  - `use-analysis-form.ts:99` 的放弃编辑确认 → `useConfirm`。
- **告知类**：操作结果统一走 FlashMessage / 轻提示，替换：
  - `change-password-dialog.tsx:131`（密码修改成功）；
  - `rich-text-editor.tsx:199,204`（润色选区提示）。
- **表单类**：富文本链接输入用 `prompt`（`rich-text-editor.tsx:46`）→ 换成小 Dialog + Input。
- **防回潮**：ESLint / oxlint 启用 `no-alert` 规则（`allow: []`）。

#### 补充设计 · 请求层全局 Toast 机制（`lib/api.ts:118` 专项）

登录过期提示发生在请求层（fetch 拦截器内）、React 树之外，`useConfirm` / `FlashMessage` 均为组件内 hook 无法直接调用，是本方向唯一需要新增基础设施的点：

- **机制选型**：新建 `stores/toastStore.ts`（zustand，与现有 `authStore` 同模式），暴露 `pushToast({ variant, message })` 纯函数；`App.tsx` 根部挂载唯一 `<ToastContainer />` 订阅渲染。请求层直接 `import { pushToast } from '@/stores/toastStore'` 调用，绕开 React 树限制（zustand store 本身可在组件外写入）。
- **401 并发去重**：原生 alert 是同步阻塞、天然防重复；改非阻塞 Toast 后，多请求同时 401 会弹出多条。对策：`toastStore` 内维护 `dedupeKey`（如 `'auth-expired'`），相同 key 的 Toast 在展示期内（如 5s）只入队一条。
- **登录过期行为**：提示「登录已过期，请重新登录」Toast（warning 态）+ 延迟 1.5s 跳转 `/login`（带 `sessionExpired` 标记，复用登录页已有的过期横幅逻辑）；跳转前清空 authStore，避免残留会话再次触发 401 风暴。

### 方向 2 · 信息架构补全：消灭占位页断层（对应 P0-2、P0-3）

- **短期**：
  - `receivable-aging` 占位卡直接内嵌"前往往来账龄分析"跳转按钮（数据现成，在 `/transactions/aging`）；
  - `cash-flow` / `inventory-aging` 占位卡给出预计上线时间或需求登记入口，将死胡同变成通道。
- **中期**：三个占位 Tab 在 `module-tabs.ts` 加"建设中"角标（Badge），管理用户预期。
- **互斥逻辑组件化**：`CompanyMultiSelect` 内置 entity/summary 互斥——勾选某类时另一类选项直接禁用置灰，替代 3 处复制粘贴的事后 alert（见 P0-3）。
  - **现有变体兼容**：组件现有三种用法需保证行为不变——`entitiesOnly`（`data/browse.tsx`，仅单体公司，天然无互斥场景，直接短路）、`selectAllType="entity"`（`overview.tsx` / `inventory/index.tsx`，全选仅作用于单体，互斥逻辑照常）、外部传 `className="w-[150px]"` 控宽（`aging.tsx`，与互斥无关）。互斥通过新增 prop `mutexByType?: boolean` 显式开启，三个调用方传 `true`，其余用法零影响。
  - **行内提示交互设计**：勾选触发互斥时（a）另一类选项立即禁用置灰并附「与已选汇总主体互斥」说明文字；（b）trigger 按钮下方渲染一条 `text-xs text-warning-strong` 行内提示「单体公司与汇总主体不能同时筛选」，带 4s 自动消失计时——选择「行内提示而非 Tooltip」是因为禁用态无法 hover 触发、且 warning 色与全站预警语义一致。

### 方向 3 · 设计系统收敛（对应 P1-4、5、8 与 P2-11）

- **字号 token 化**：tailwind.config 增加语义字号：
  - `text-micro`（10px，仅装饰性后缀，如"万"字单位）；
  - `text-caption`（11px）；
  - `text-helper`（12px）；
  - 批量替换 46 处任意值；**正文最小字号红线 12px**。
  - **lint 边界约束**：class 层 lint 只能拦 `text-[10px]` 任意值（拦不住语义 token 的误用），故补两条硬约束——① `text-micro` / `text-caption` 仅允许出现在 `components/` 白名单组件内（单位后缀、角标、图表轴标签等装饰场景），页面级组件禁止使用；② code review 清单增加「正文/数据区是否出现 micro/caption」检查项，违反即打回。
- **FilterBar 标准化**：新增 `FilterBar` 布局组件：
  - 统一 `h-9` 控件高、间距 `gap-3`、可换行、吸顶；
  - 控件宽度语义常量化（`w-[180px]` 主体 / `w-[140px]` 期间）；
  - 看板与往来页全部收编。
- **EmptyState 统一**：抽 `EmptyState` 组件（图标 + 标题 + 描述 + 可选动作按钮），看板空态卡、inventory EmptyHint、DataTable emptyText 三轨合一。
- **路由级骨架**：`App.tsx` 的 Suspense fallback 换成页面壳骨架（页头占位条 + KPI/表格骨架），与页内骨架体系连续。

### 方向 4 · 大文件拆分（只拆最痛的 4 个，对应 P1-7）

| 文件 | 现行数（含空行） | 拆法 |
|------|--------|------|
| `pages/data/import-panel.tsx` | 999 | 拆出 `UploadZone`、`BatchQualityPanel`、`ImportConfirmBar` 三组件 + `useImportFlow` 状态机 hook |
| `pages/indicators/index.tsx` | 840 | 拆 `IndicatorFilterBar`（筛选+列设置+密度）、`useIndicatorExport`；三类科目 adapt 映射独立成 `indicators-adapters.ts` |
| `pages/inventory/index.tsx` | 887 | 互斥校验入共享 hook；公司×品类明细表拆独立组件 |
| `pages/admin/dialogs.tsx` | 772 | 用户编辑/密码重置/删除确认按对话框拆文件 |

其余（formula-maintenance 915、collections-tab 648、admin/roles 596、coverage-tab 568）随功能迭代逐步拆，不专项立项。

### 方向 5 · 细节打磨（对应 P2-9、10、12）

- **KPI 卡可点击性**：hover 时右上角淡入 `ArrowUpRight` 图标 + `translateY(-1px)` 微升 + 边框转 primary 色，让"可钻取"可感知。
- **达成率阈值配置化**：75/60 提为 `constants.ts` 常量并配注释，供后端口径联动。
- **导出体验统一**：所有导出按钮统一 loading 态 + FlashMessage 结果反馈（替换 `aging.tsx:242`）。

## 四、实施路线图

| 阶段 | 内容 | 交付物 / 验收标准 | 回归策略 |
|------|------|-------------------|----------|
| **Phase 1（快赢）** | 方向 1 全部（含请求层 Toast 机制先行设计）+ P0-2 占位页跳转 + `no-alert` lint | 交互反馈 100% 体系内，零原生弹窗（lint 强制） | 弹窗改 Dialog 的页面逐一手工冒烟：确认/取消/ESC/点击遮罩四路径；401 过期链路跑 `e2e-multisession.mjs` 验证并发去重 |
| **Phase 2** | 方向 3 设计系统收敛（字号 token、FilterBar、EmptyState、路由骨架） | 新增 3 个基础组件 + lint 约束，任意值字号清零 | 跑现有 vitest（data-table / kpi-card / collapsible 等组件测试）+ 主题三风格 × 看板/往来/指标三页截图比对 |
| **Phase 3** | 方向 4 大文件拆分 + 互斥逻辑组件化 | 4 个文件均 < 400 行，互斥校验单一来源 | 纯结构性重构不 diff 业务逻辑；互斥三页（总览/账龄/存货）手工验证三种 `CompanyMultiSelect` 变体行为不变 |
| **Phase 4** | 方向 5 打磨 + 移动端表格卡式化评估 | 视觉细节清单清零 | `prefers-reduced-motion` 下动效降级验证 + 窄屏（<1280px 侧边栏折叠、<lg 移动抽屉）冒烟 |

**Phase 1 开工前置条件**：先完成「请求层全局 Toast 机制」设计评审（见方向 1 补充设计），这是唯一需要新增基础设施的点。

**优先级依据**：P0 三项均为用户可感知的体验断层（原生弹窗、死胡同占位页、事后报错式互斥），改动小收益大；P1 是维护性投资；P2 属打磨。所有建议均不破坏既有设计令牌与三套主题机制。

**评审提出的修正与补充（已合入本文档）**：

1. **数字口径修正**：原生弹窗 17→15 处（原口径含 2 处注释提及）；任意值字号涉及 22→20 个文件；超大文件行数改为含空行实测口径（999~568，原口径不含空行偏低约 4%）。
2. **请求层 Toast 机制补全**（→ 方向 1 补充设计）：`lib/api.ts:118` 位于 React 树外无法调用组件 hook，明确 zustand `toastStore` + 根部 `ToastContainer` 方案，并设计 401 并发去重与跳转时序。
3. **互斥组件化兼容性补全**（→ 方向 2）：覆盖 `entitiesOnly` / `selectAllType="entity"` / 外部 className 三种现有变体，经 `mutexByType` prop 显式开启；行内提示交互设计落地为「禁用置灰 + warning 色行内文字 4s 自动消失」。
4. **字号 token lint 边界补全**（→ 方向 3）：lint 拦不住语义 token 误用，补组件白名单 + code review 检查项双约束。
5. **回归测试策略补全**（→ 路线图）：每 Phase 增加回归列——弹窗四路径冒烟、现有 vitest 全量、三变体行为验证、动效降级与窄屏冒烟。
