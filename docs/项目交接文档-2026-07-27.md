## 1. 本次核心变更：重分类功能重构

### 1.1 需求背景

原有重分类仅支持"整行改挂"（把源公司整条事实数据改挂到目标公司）。本次重构实现两大能力：

1. **跨公司部分金额转移**：将部分金额（按比例或按固定金额）从源公司转移到目标公司——源行 value 调减（行保留），目标公司同唯一键行调增，无对应行则新建，总额守恒。
2. **同公司科目间调整**（全新）：源科目调减、目标科目调增，两者金额**可以不相等**（典型场景：修正某科目重复计算时只减不增），公司总额可能变化，必须填写调整原因留痕。

### 1.2 关键设计决策

- **汇总主体与 YTD 累计无需物化重算**：经核实 `AggregationService` 中汇总主体为查询时展开成员公司（`resolveCompanyCodes`）、YTD 为查询时区间求和，事实行变更后自动生效；前端仅需失效相关查询缓存。
- **金额分摊算法**：以"分"为单位整数运算避免浮点误差；按各行 value 占比分摊，尾差在有容量的行间微调，保证分摊合计恰等于输入金额，且每行分摊额不超过该行余额。
- **向后兼容**：`transferMode` 默认 `'all'` 保持原整行迁移语义（冲突合并求和并删源行），现有调用与测试不受影响。
- **科目间调整与"科目树换父"区分**：原 `DataService.reclassifySubject`（科目树换父，路由 `POST /subjects/:id/reclassify`，日志 type=`subject`）保持不动；新功能为事实数据金额调整，日志 type=`subject_adjust`。

## 2. 代码变更详情

### 2.1 后端

#### `server/src/services/ReclassificationService.ts`（重构，245 → 约 560 行）

- `ReclassifyCompanyParams` 新增 `transferMode: 'all' | 'ratio' | 'amount'`、`ratio`（0 < r ≤ 1）、`amount`（> 0）。
- `PreviewResult` 扩展为 `{ affectedRows, totalValue, transferValue, conflictRows, createRows }`。
- 内部重构为 `tableOps(db, templateType)` 适配器（operating/static/budget 三张事实表统一 where 构造、期间键 `periodKeyOf`、新建行 `createData`）。
- 新增分摊函数：
  - `allocateAmount(values, amount)`：分单位按占比分摊 + 容量上限 + 尾差微调（负值明细报 400、超额报 400）。
  - `allocateByWeights(weights, amount)`：按权重分摊（无上限），用于调增额按调减分布分摊。
- 执行路径：`transferAll`（原整行迁移语义）与 `transferPartial`（源行调减保留——即使减到 0、目标同键行累加、无则新建）。
- 新增 `previewAdjustSubject` / `adjustSubject`：
  - 参数 `AdjustSubjectParams = { templateType, companyCode, sourceAccountCode, targetAccountCode?, decreaseAmount, increaseAmount?, periodFrom?, periodTo?, reason }`。
  - 校验：公司存在且在操作者 scope 内；科目存在（静态模板对应静态科目，否则经营科目）且源目标不同；调减额 ≤ 源科目匹配行合计；调增 > 0 时必须有目标科目；`reason` 必填。
  - 日志：`reclassificationLog` type=`subject_adjust`，`sourceCompany`=公司、`sourceSubject`/`targetSubject`、detail 含 `{ decreaseAmount, increaseAmount, netChange, reason, mergedRows, createdRows }`；同时写标准审计日志（module=data, action=reclassify）。
- 所有执行均在 `prisma.$transaction` 中完成，失败整体回滚。

#### `server/src/routes/data.ts`

- 提取 `companyReclassifyBody()`：解析并校验 `transferMode/ratio/amount`（非法 transferMode 报 400）。
- 新增端点（权限点复用已有 `data:reclassify:subject`）：
  - `POST /api/v1/data/reclassify/subject/preview`
  - `POST /api/v1/data/reclassify/subject`
- 原有 `POST /reclassify/company(/preview)`、`GET /reclassify/logs`、`POST /subjects/:id/reclassify` 行为不变。
